# Архитектура

[← К README](../README.md)

## Поток запроса

Nginx отдаёт существующие файлы из `public/` или внутренне передаёт запрос в `public/index.php`. Точка входа запускает сессию, разрешает маршрут, собирает зависимости и передаёт работу контроллеру. Контроллер получает данные из репозитория, рендерит шаблон и возвращает HTML.

Для изменения фильтра браузер запрашивает `/ajax-filter`; в ответ приходит только HTML списка товаров, который заменяет текущий блок результатов.

## Точка входа и маршруты

[`public/index.php`](../public/index.php) — application entrypoint и composition root. Здесь подключается bootstrap, запускается сессия, создаются `DatabaseConfig`, PDO, `ProductQueryBuilder`, `ProductRepository`, `ProductFilter`, `ViewRenderer` и контроллеры.

Приложение обрабатывает ровно два пути:

- `/` — `HomeController::index()` собирает полную страницу каталога;
- `/ajax-filter` — `FilterController::filter()` возвращает HTML-фрагмент товаров.

## Нативный autoload `App\`

[`app/bootstrap.php`](../app/bootstrap.php) регистрирует простой autoloader для пространства имён `App\`. Он принимает только имена классов с допустимыми сегментами и сопоставляет их с PHP-файлами внутри `app/`. Composer в этом потоке не используется.

## Контроллеры и фильтры

`HomeController` читает активные критерии из сессии, получает товары и значения для трёх select-полей, затем рендерит `products`, `home` и `layout`.

`FilterController` нормализует query-параметры, применяет их к сессии и рендерит только `products`. `ProductFilter` принимает лишь `category`, `color` и `weight`; пустые и не-скалярные значения игнорируются. Значение `all` очищает только соответствующий фильтр в сессии, а не связанные с приложением данные. Непереданные фильтры остаются активными; кнопка сброса на клиенте отправляет `all` для всех трёх полей.

## Доступ к данным

`ProductRepository` получает список товаров, категорий, цветов и весов через PDO. Для выборки товаров `ProductQueryBuilder` формирует SQL только с allowlisted идентификаторами `category`, `color`, `weight`; значения передаются в native prepared statement. `ConnectionFactory` создаёт PDO с исключениями, associative fetch mode и отключённой эмуляцией prepare.

## Конфигурация базы

`DatabaseConfig` объединяет значения в таком порядке: встроенные defaults → `config/database.php`, если файл есть → переменные окружения `DB_*`. Более поздний источник переопределяет предыдущий. Класс проверяет набор ключей локального файла и корректность обязательных строк, порта и `charset` до подключения к базе.

## Рендеринг и escaping

`ViewRenderer` работает только с зарегистрированными шаблонами `layout`, `home` и `products`; имя шаблона нельзя подставить из запроса. Динамические scalar-значения, например title и свойства товаров, выводятся через `ViewRenderer::escape()` с `htmlspecialchars` и UTF-8. Уже отрендеренные внутренние HTML-фрагменты — `$content` и фрагмент товаров — передаются между шаблонами как trusted rendered HTML.

## Ответственность frontend

`public/assets/js/ajax-filter.js` следит за select-полями, отменяет предыдущий незавершённый запрос через `AbortController`, отправляет изменённый фильтр на `/ajax-filter` и заменяет HTML результатов. При сбросе он посылает `all` для каждого поля.

`public/assets/js/ui.js` отвечает за выбор светлой, тёмной или системной темы, переключение русского и английского интерфейса, хранение этих предпочтений в `localStorage`, а также обновление текстов во фрагменте после AJAX-ответа.

## 404 и 500

Неизвестный путь получает статус `404`, шаблон `templates/error/404.php` и заголовок для возврата на `/` через 10 секунд. Любое необработанное исключение логируется на сервере; клиент получает статус `500` и короткий plain-text ответ без деталей исключения.

## Что намеренно не добавлено

В проекте нет отдельного router-класса, DI-контейнера, ORM, фреймворка, Composer-зависимостей, frontend-фреймворка и отдельного API-слоя. Сборка зависимостей остаётся явной в entrypoint, чтобы демонстрационный поток был легко проследить по коду.
